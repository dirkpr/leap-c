# Plan: system-identify the BOPTEST RC prediction model

## Context

The current BOPTEST example (`leap_c/examples/boptest/`) uses a hand-crafted
R1C1 model with **rough, un-fitted** R/C/gain values. That is enough to confirm
signal wiring, but the prediction model is not faithful, so the MPC cannot
control well and there is no trustworthy baseline to learn on top of. BOPTEST
exposes no state-space model (the emulator is a black-box Modelica FMU), so the
next step is to **identify the RC model from data** generated by the emulator.

This grey-box, once fitted, replaces the rough defaults in `acados_ocp.py`; the
parameters stay differentiable, so the identified values become the
initialization for later learning.

## Goal and success criteria

Fit the R1C1 (and optionally R2C2) parameters so that, on **held-out** data:

- multi-step (free-run) zone-temperature prediction RMSE over the MPC horizon
  (N * step_period, e.g. 3 h) is **< ~0.5 K** (target; tighten with R2C2);
- residuals show no strong bias correlated with the disturbances;
- closed-loop KPIs from `scripts/boptest/run_baseline.py` **improve** vs the
  hand-tuned model (lower `tdis_tot` at equal-or-lower `ener_tot`).

## Approach

### 1. Collect an identification dataset
Drive the emulator with an excitation signal and log inputs, state and
disturbances. New script `scripts/boptest/collect_id_data.py`:
- Excite `oveHeaPumY_u` with a **multilevel PRBS / amplitude-modulated** signal
  (steps + pseudo-random holds) spanning [0, 1], to excite the thermal modes
  across the operating range. (Comfort violations during offline ID are
  acceptable; optionally clamp excitation to stay near the band.)
- Sampling: `step_period = 900 s` (optionally finer, e.g. 300 s, to capture
  faster modes). Simulate 1-2 weeks of representative winter weather; split into
  train / validation windows.
- Log per step: `reaTZon_y` (T), applied `oveHeaPumY_u` (u), **measured
  delivered thermal power** `reaQHeaPumCon_y` and electrical `reaPHeaPum_y`, and
  disturbances `TDryBul` (T_amb), `HGloHor`/`HDirNor` (solar), plus
  `InternalGainsRad[1]`. Pull disturbances via `/forecast` or `/results`.
- Save to parquet/csv under the scratch/output dir.
- **Verify:** dataset covers the T and u ranges, has no NaNs, and both train and
  validation windows exist.

### 2. Fit the grey-box RC (+ heat-pump map)
New script `scripts/boptest/identify_rc.py`:
- **Decouple the heat pump from the envelope**: fit the envelope RC using the
  *measured* delivered thermal power `reaQHeaPumCon_y` as the heat input (this
  makes R and C identifiable, which they are not from T and u alone). Separately
  fit the modulation->thermal / COP map `u -> Q_thermal, P_elec` (constant or
  affine COP as a first cut) from `reaQHeaPumCon_y`, `reaPHeaPum_y`.
- Discretize the RC with the **same exact ZOH** as `acados_ocp.py`, build the
  N-step prediction as a CasADi function, and minimize **simulation (free-run)
  error** over sliding windows with IPOPT (or `scipy.optimize.least_squares`).
  Prefer multi-step over one-step error so the model is good over MPC horizons.
- Bound parameters to the physical ranges already declared in `param_space`.
- Optionally repeat for **R2C2** (states `[T_air, T_mass]`) for better multi-step
  accuracy.
- **Verify:** optimizer converges; fitted params are within bounds; train RMSE
  is small.

### 3. Validate on held-out data
- Report held-out multi-step prediction RMSE over the horizon and a residual /
  whiteness check; plot predicted vs measured T.
- **Verify:** held-out horizon RMSE meets the target (< ~0.5 K).

### 4. Integrate the identified model
- Replace the rough defaults in `export_parametric_ocp` (or add a small
  fitted-params loader keyed by test case) with the identified values; keep the
  COP/heat_gain map consistent with the fitted heat-pump characteristic.
- Keep all parameters **differentiable** so the fitted values seed later tuning.
- **Verify:** `run_baseline.py` closed-loop KPIs improve vs the hand-tuned model.

## Files to add / touch
- `scripts/boptest/collect_id_data.py` - excitation + logging.
- `scripts/boptest/identify_rc.py` - fit RC (+ heat-pump map), write params.
- `leap_c/examples/boptest/acados_ocp.py` - identified defaults / params loader.
- `tests/leap_c/examples/test_boptest.py` - add a hermetic test asserting
  prediction RMSE below a threshold on a small **cached** ID dataset (so it runs
  offline, no server).
- Optional: a wiki note recording the identified model and fit quality
  ([[leap-c/boptest-example]] companion).

## Risks / considerations
- **Heat-pump nonlinearity**: COP varies with source/supply temperature and the
  compressor has a minimum modulation / on-off behavior; a constant COP is a
  first approximation only. Using measured `reaQHeaPumCon_y` as the RC input
  sidesteps this for the envelope fit.
- **Identifiability**: R and C are correlated; only `tau = R*C` and the gain are
  identifiable from T with an unmeasured heat input - measuring delivered thermal
  power resolves this (hence the decoupling in step 2).
- **Solar model**: which irradiance component (global vs direct+diffuse) and the
  effective aperture `a_sol`; validate the solar contribution separately.
- **Coverage / overfitting**: cover enough weather variation; validate on a
  different period/season than training.
- **Excitation vs comfort**: aggressive excitation violates comfort; acceptable
  offline, but keep it representative of the closed-loop operating region.
